Today claude-setup turns on all 8 luismc plugins in .claude/settings.json. Turning a plugin on is not the same as enforcing it:

  • The docs plugin does nothing until docs/docs.json exists. In a project that already has docs, claude-setup only shows a dry run of migrate.
  • The design system has no step in claude-setup at all. It needs design-system-setup, guard tests in the test runner, and an approved v1.
  • The delivery plugin's hooks block inside Claude sessions. Merges by people or other tools are stopped only by CI and branch protection, which claude-setup does not touch.
  • At the end, claude-setup does not say which plugin is active, which only warns and which blocks.

The change: claude-setup goes through every plugin and every other dev-standards setup, asks the owner which to start enforcing, does the setup for each yes, and ends with an enforcement report. Every write stays a file in the working tree. claude-setup never touches git.
