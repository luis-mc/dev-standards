§ 1What and why

Today claude-setup turns on all 8 luismc plugins in .claude/settings.json. Turning a plugin on is not the same as enforcing it:

  • The docs plugin does nothing until docs/docs.json exists. In a project that already has docs, claude-setup only shows a dry run of migrate.
  • The design system has no step in claude-setup at all. It needs design-system-setup, guard tests in the test runner, and an approved v1.
  • The delivery plugin's hooks block inside Claude sessions. Merges by people or other tools are stopped only by CI and branch protection, which claude-setup does not touch.
  • At the end, claude-setup does not say which plugin is active, which only warns and which blocks.

The change: claude-setup goes through every plugin and every other dev-standards setup, asks the owner which to start enforcing, does the setup for each yes, and ends with an enforcement report. Every write stays a file in the working tree. claude-setup never touches git.

§ 3How each offer is enforced

There are four levels. The first two stop work. The last two only inform.

  • Blocks in session: a Claude hook denies a tool call or blocks the end of a turn. It works only in Claude sessions with the plugin on.
  • Blocks merge: a CI check that is required on the default branch. It works for everyone, people and tools.
  • Warns: a hook prints a message. Nothing stops.
  • None: run on demand.

§ 4How the owner sees it

The flow keeps today's rule: ask first, plan everything, confirm once, then apply.

  1. Target question (today): project, user or both, and the effort level.
  2. Status scan, with no writes: each offer is done, missing or broken.
  3. One question page per group, in a single AskUserQuestion call. Each question carries its own context.
    • Enforce: docs, design system, delivery, project record (multi-select; done ones are left out).
    • Delivery mode: warn first, or block now.
    • CI: write the checks workflow, and print the branch-protection command.
    • Other setups: tech-stack-setup audit, auth-setup, one audit run (multi-select, all off by default).
  4. One change plan listing every file and command, confirmed once (step 3 today).
  5. Apply and verify.
  6. Enforcement report: one line per plugin, its level, and the next step when it does not block yet.

The report, as the owner would see it:
