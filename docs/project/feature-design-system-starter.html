§ 1What and why

design_system.py init writes docs/design-system/next-version/ from the docs plugin's template. Today that template holds 4 example rules, 2 components and 9 tokens. The owner has to write the whole system before the guard tests have anything to check.

The starter replaces it with a full, neutral system: about 20 generic UX rules with rule IDs, about 20 shared components, a complete token set with light and dark themes and system fonts, and an action vocabulary in content.md. Every item is marked as a starter item to keep, change or delete. Nothing in it names a product, a domain or a past decision.

When the project already has styles (theme files, Tailwind configuration, CSS custom properties), the skill lists what it found, asks once, and fills the token values on a yes. On a no, or when nothing is found, the starter values stay.

Approval does not change: v1 still needs the owner's recorded approval after the review gallery, so a starter never becomes binding unread.

§ 2What the starter holds

FileHolds
ux-rules.mdRule table UX-1 onward: consistent; reuse components; clear headline and plain words; one primary action labelled by what it does, with its reason; guided flows as a wizard (step bar, one step, Back and the primary); no dead ends; never act on hidden items; only buttons look like buttons; in-page confirmation, never browser dialogs; aligned boxed sections in one grid; one pager for long lists; select all and clear on choice lists; busy buttons; core content first; use the width; phone and desktop for every screen, 44 px targets; accessibility (WCAG 2.2 AA, focus, reduced motion, text for every status); dates, times and numbers one way; status from one source of truth. Each rule names its guard or none yet.
components.mdPage header; top menu and breadcrumbs; tabs; wizard; sticky action bar; action rows; buttons; card and card grid; facts list; pager; list toolbar (search, filters, count, view toggle); segmented choices and filter chips; one-choice list; form field family (field, toggle, check box); tables and list rows; progress bar (known and unknown total); badges and counts; messages (four tones) and banner; empty, failed and error states; dialog and sheet; selection bar.
tokens.md--ds-* tokens: colour roles for light and dark, type roles (page title to hint), type scale, spacing scale, radius, shadows, breakpoints, motion. System font stacks only.
content.mdThe action vocabulary (one word per action and the words never to use: Remove, Delete, Clear, Stop, Try again, Refresh, Hide …), message wording patterns, date and number formats.
README.md, CHANGES.mdOrder of work and the starter's change log entry.

§ 3Left out of the starter, and how to bring it in

The owner's reference design system (a mature v4 draft) was read as a pattern only. These parts are not in the starter.

Left outWhyOptions to bring it in
