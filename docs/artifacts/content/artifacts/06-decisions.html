#QuestionDecision (10 Oct)
1How is a task’s status stored so both artifacts update automatically?One task registry inside the full-progress artifact; both checklists are generated from it.
2Do branch names start with the task ID?Yes (AR5-artifactspec), so hooks can match events to tasks.
3How do changes made outside a session reach the artifacts?At the next session start, through the session-start hook. No cloud routine in 1.0.
4What look do artifacts get?The project’s own design, found by scanning its design files, theme configuration, CSS custom properties or live site. A project with no design gets the plugin’s default design. dev-standards uses the default.
5An App / service column on the full-progress artifact?Yes, on the full-progress artifact only.
6Where is the record kept?In the repo, docs/artifacts/, committed to the default branch as docs-only commits; a deleted artifact is recreated from it without duplicates. Replaces the first answer that the published artifact is the record.
7How does a project get the plugin?luismc-project-setup installs it in every project it sets up; it can also be installed on its own in any project. No artifact is created until the first feature artifact.
8Which clock do Expected times use?The owner’s time zone, per project, set in the manifest and named in the column header.
9Does dev-standards move other projects onto the plugin?No. dev-standards ships the plugin and names or changes no other project; each project adopts it in its own sessions.
