A summary of ARTIFACTSPEC 1.1.0 (plugin 1.1.2). Each rule has an ID here so the checks and reviews can cite it; the spec numbers its requirements by section (R3.1, R6.9 and so on). Changes since 1.0.0 are marked.

Kinds and tasks

IDRule
AS1A project has feature artifacts and exactly one full-progress artifact. Creating the first feature artifact creates the full-progress artifact if none exists.
AS2A feature artifact is titled Feature: plus the feature name. It covers one app, several, or the whole project, and changes as the feature evolves. Its last section is History: Date | Change, newest first.
AS3The full-progress artifact is titled Full Progress: plus the project name. It shows all ongoing work in the project, across every app and service: every feature task, linked to its feature artifact, and every project task. It has no History; only Live rows older than 14 days fold into an “Earlier” block. Built rows never fold, so unreleased work is not hidden. It is the only artifact published to claude.ai.
AS4Every task has an ID: a prefix registered in the manifest plus a number. IDs are unique across the project and never reused.
AS5Each task’s state is stored once, in the task registry docs/artifacts/registry.json, committed in the project’s repo and embedded in the full-progress artifact. Every checklist and tile count is generated from it; no status row is typed by hand.
AS6The manifest docs/artifacts/manifest.json names the project, its timezone, its design, the full-progress artifact, and each feature artifact with its link, task prefix and files.

Look and structure

IDRule
AS7Every artifact of a project uses the shared structure stylesheet unchanged, plus the project’s design tokens: taken from the project’s own design (design-token files, theme configuration, CSS custom properties or its live site), or the plugin’s default design when it has none. Artifact-only drawings may add styles but never change shared ones.
AS8Sections are numbered from 0 in order with no gaps; the contents list shows the same numbers. Section 0 is Status and checklist: stamp, lede, tiles, key and checklist, in that order.
AS9The stamp reads Last update: DD Mon HH:MM (<timezone label>), with the full ISO time in its datetime attribute, taken from the real clock at the moment of the change.
AS10The lede says in plain words what stands and what needs the owner, or “Nothing needs you”.
AS11The checklist columns are Status | Item | Detail | Expected. Rows are grouped: Running now and next (Running, Waiting, To do), Needs you, failed or on hold (Needs you, Failed, On hold), Live or built, newest first. The full-progress artifact adds an App / service column after Item. Expected is a date, with a time for work due within a day (10 Oct ~14:15), in the owner’s time zone. The zone is set once in the manifest and named in the column header. Never “today” or “soon”. When an expected time passes, a new estimate replaces it.
AS12Eight statuses with fixed colours and meanings: Live released or in production; Built finished, not released yet (this was Done in 1.0.0); Running being worked on now; Needs you waits on the owner; Waiting waits on something else (CI, a dependency, a time); To do planned, not started; On hold paused by decision; Failed broke and needs a fix or a decision.
AS13Artifacts work in light and dark themes, and at phone width with a 16 px side gutter and no sideways page scroll; wide tables scroll inside their box.

Keeping them current

IDRule
AS14A feature task’s status change updates its feature artifact and the full-progress artifact; any other project task’s change updates the full-progress artifact. One command does both. Full Progress is published once per turn, at the end, never mid-turn; feature artifacts are files in the repo and are not published.
AS15Every activity is recorded as a task first, whoever does it: work given to agents and the session’s own (contracts, specs, reviews, joins, test runs, releases, deploys, cleanup). A task is Running while any work for it runs. Release steps still to come for Built work are their own task.
AS16Branch names start with the task ID, so hooks can match events to tasks.
AS17A turn may not end while a status change is queued, Full Progress is unpublished, or a turn that started background work has no Running task.
AS18Times are shown in the owner’s timezone and labelled with it.
AS19A project’s artifacts can be recreated from docs/artifacts/ alone. A new artifact is created only when the manifest link no longer opens and no artifact with the same title exists.
AS20Status changes are committed to the default branch as docs-only commits; CI and hosting skip docs-only changes.

Added in 1.1.0 and 1.1.1

IDRule
AS21The rule is delivered to every project by the plugin at each session start. It is not copied into the project, and check notes a stale copy.
AS22A feature artifact records every option the owner was offered in decisions.json, drawn as option cards: Recommended, the owner’s choice with its date and words, Not chosen, and an open decision as Needs you.
AS23Publish budget: claude.ai allows 200 artifact publishes a day per account and every republish counts. Only Full Progress is published, once per turn. A feature artifact is a standalone HTML file in docs/artifacts/, opened in a browser. The two older claude.ai feature artifacts were deleted on 10 October at the owner’s request.
AS24A writing command refuses a change that adds a finding, but may leave findings that were already there (1.1.1). A record is repaired one artifact at a time.
