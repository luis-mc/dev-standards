§ 1What and why

Which model runs which work is a design decision with a cost, so it is specified, versioned and tracked like any other feature.

The owner’s rule (10 October): the definition of which model each agent type uses, and each skill’s profile, is always a feature. The 9–10 October evidence from a real project’s sessions showed why:

  • Merging, conflict resolution, lint fixes and running checks were mechanical. Design contracts, scope and judgment calls were the only work that needed the strongest model.
  • 18 parallel cloud agents used up the 5-hour session limit in about 20 minutes; five at a time finished the same work.
  • Effort was set by hand (effortLevel: high in that repo’s settings on 10 October), not by the setup every project gets.

Where it stands (11 October). The owner first asked for Sonnet at high, then confirmed “Sonnet medium everywhere”. The default is now medium for both models, in every skill profile, in claude-setup and in the agent rules (MP7). The owner’s own ~/.claude uses medium for both, and the installed plugins were updated to match.

§ 2Today

Figure 1 corrects the first inventory given in the session: Explore and Plan are not on Sonnet. They run on the main session’s model, so in these projects they run on Opus. Only general-purpose code agents and plugin agents without a model of their own follow CLAUDE_CODE_SUBAGENT_MODEL.

§ 3Where model and effort come from

Two settings carry most of the weight. CLAUDE_CODE_SUBAGENT_MODEL only applies when nothing above it names a model. Per-model effort (modelSettings) is not documented to reach subagents, which is why DS5 also passes the effort on each Agent call.

A skill’s model and effort go in its SKILL.md frontmatter. The model applies for the rest of the turn that runs the skill; the session model resumes on the next prompt. The skills of luismc-artifacts are in the table too.

What changed on 11 October (MP7). Before, judgment skills ran on Opus at high, claude-setup and code agents on Sonnet at high, the top-level effortLevel was high, and the architect used the main session’s effort. All of these are medium now. The agent rules tell the main session to pass effort: "medium" on every Opus or Sonnet Agent call, and claude-setup preselects medium for both models.

§ 7Decisions

D5 Saved effort when an alias moves?

Asked 10 Oct · Decided 10 Oct

Warn at session start Recommended Chosen by the owner · 10 Oct

A session-start hook checks that the current Opus and Sonnet IDs have an effort entry and tells you to re-run claude-setup if not. Aliases keep following new models.

Pin full model IDs Not chosen

Settings name exact IDs (claude-opus-5-5) everywhere, so nothing drifts; new models are adopted only when claude-setup is re-run.

D4 Per-skill profiles?

Asked 10 Oct · Decided 10 Oct

By kind of work Recommended Chosen by the owner · 10 Oct

Judgment skills (spec-new, the three audits, tech-stack-setup, auth-setup) on Opus at high; mechanical skills (spec-check, project-artifact-check, task-add, task-status-update) on Sonnet at medium; claude-setup on Sonnet at high.

All inherit the session Not chosen

No per-skill model or effort; every skill runs on whatever the main session uses.

D3 Override Explore and Plan?

Asked 10 Oct · Decided 10 Oct

Explore on Sonnet, Plan on Opus Recommended Not chosen

The plugin ships an agent named Explore pinned to Sonnet (search is mechanical); Plan stays on Opus (it is design work).

Explore on Haiku, Plan on Opus Not chosen

Cheapest search; Haiku may miss subtle matches in large repos.

Leave both on Opus Chosen by the owner · 10 Oct

No override; highest quality, highest cost.

D2 Where do the role rules live?

Asked 10 Oct · Decided 10 Oct

Plugin-owned rule file Recommended Chosen by the owner · 10 Oct

Install the block as .claude/rules/agents-and-integration.md, replaced on every run like model-delegation.md. Reaches every project, including ones with a hand-written CLAUDE.md. The CLAUDE.md template drops those sections.

CLAUDE.md template only Not chosen

Put the block in the CLAUDE.md template. Only projects without a CLAUDE.md get it.

D1 Effort for each model of the split?

Asked 10 Oct · Decided 10 Oct

Fixed: Sonnet high, Opus asked Not chosen

Code agents always high (per-model entry + the Agent call's effort), plus top-level effortLevel high for cloud agents. The setup asks only the Opus main-session effort. DS5 is reworked to this and folded into DS6.

Fixed: everything high Not chosen

No question at all. Top-level effortLevel high and both per-model entries high. DS5's question is dropped.

Keep asking, high preselected Chosen by the owner · 10 Oct

DS5 ships as built, but high is offered as the default answer for code agents, and top-level effortLevel high is added for cloud agents.
