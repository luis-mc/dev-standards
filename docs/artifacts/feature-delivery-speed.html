§ 1What and why

The owner brought a prompt measured in one product over seven days: 82 releases, 971 workflow runs, 3,039 CI jobs. Its diagnosis matches what dev-standards found about itself (see Feature: Test and validation cost): the problem is not the number of tests but that each delivery layer reruns the full suite instead of doing its own share. A finished change also waits for its whole train, and pushes to a train branch keep restarting CI.

  • Each change ran the full suite 4 to 6 times: 1 to 3 agent gates, the join gate, PR CI, and a default-branch run on the same tree.
  • 56% of CI job-minutes went to cancelled or failed runs, most of the cancels from pushes to a train branch while its CI ran.
  • In one traced release, tests ran 51 of the 492 minutes from built to live. The rest was waiting for cargo, restarted CI, and 3 hours queued for the only runner with a required label, which was offline.
  • A gate result went stale only because the default branch moved by docs-only commits.
  • A packaged program shipped with a worker that never started while every test passed, because no test ran the packaged form.

The numbers describe one product and stay here, not in the specs. The work changes luismc-project-setup (STACKSPEC 13.5 and 13.6, the delivery scripts, the agents rule) and is released as STACKSPEC 8.0.0 after the TC6 train merges, because it builds on that train's join change (DS45).

§ 2The plan (rewritten prompt)

The owner's prompt, reviewed on 11 October and rewritten with the review's fixes and the owner's answers (decisions below). Order matters: each step builds on the one before.

TaskChangeSettled by the review
DL1Stale results. gate.json gets inert_paths (default docs/**; tech-stack-setup adds docs/artifacts/** when luismc-artifacts is enabled). gate_verify.py keeps a result valid when the base moved only by commits touching inert paths.Written by the setup, not declared by a sibling plugin. Trusted only because the ready PR's CI still tests the real merge.
DL2Quick join check. join.py replaces the second full gate with install, build, typecheck and the tests of the union of the branches' affected packages plus their dependents; it keeps TC6's skip when the joined tree equals a trusted branch head. The join report records per-step times.Builds on DS45 (TC6). Union plus dependents (D6).
DL3Agent rule. Locally an agent runs the affected suites only; a full suite only when its change trips a full-run valve; never a branch CI run unless the change behaves differently on Linux.Merged with DS45's rule, which is stricter on CI.
DL4Gate scope. Steps already scope by package (changed, changed+dependents, widen_on). New: a lockfile change widens only when it changes an affected package's dependencies; a shared-UI change runs the end-to-end tests of the apps that import the changed files (from imports, so e2e_map becomes optional). --full stays.Half of the original point existed already.
DL5Build-artifact workflows (installers, bundles, packages) run only when the paths that feed them change; never for docs-only or record-only merges.Extends 7.1.0's ci_skip_check.
DL6Train freeze. Once the ready PR opens, the pre-push hook refuses pushes to that train branch until its CI finishes (pass or fail, so fix forward works) or the train is abandoned (the ready PR closed unmerged). Offline it allows the push and warns. DELIVERY_FREEZE_OVERRIDE=1 allows a push and prints that the running CI will restart. Late branches ride the next train.Offline behaviour (D4), override (D9), and a definition of abandoned.
DL7Runner health. Before the ready PR opens, join.py checks that an online runner exists for every label the workflow's jobs need, and ci_watch.py warns when a job has been queued over 10 minutes with no online runner for its labels. Warnings only. Standard hosted labels count as available; without admin rights to list self-hosted runners it says so. tech-stack-setup's runner question warns against a label only one runner carries unless a fallback job exists.Warn, don't block (D5). The single-runner rule moves from generated CI to setup, which cannot know the runners.
DL8Delivery log. Before cleanup.py deletes a branch it records its finished, joined, CI start and end, and merged times; the deploy step adds live. At the end of each train the log is appended to the train's GitHub release notes, with time-to-live per change split into waiting, testing and queueing.Release notes (D3), never commits to main. Live comes from the deploy, not cleanup.
DL9Packaged smoke test (a new MUST). A product that ships a packaged program (single executable, installer, app bundle, container image) has CI start the packaged form and exercise every child process or worker it starts.MUST, so STACKSPEC 8.0.0 (D2); products claiming 7.x get it as an upgrade item.
DL10dev-standards adopts the delivery log in its own releases and the train freeze on its integration branches.Dogfood (D7, D8).

Each delivery-script change gets scenarios and mutants. Versions come from change notes: STACKSPEC 8.0.0, luismc-project-setup major.
