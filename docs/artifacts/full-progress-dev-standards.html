§ 2How it stays current

Until luismc-artifacts is built, this artifact is kept by hand to the same rules: a status change is written to the feature artifact that holds the task and to this artifact, in the same turn.

  • Project tasks (prefix DS) are work in dev-standards that belongs to no feature artifact: releases, fixes, CI, spec changes. They include changes to luismc-project-setup, such as DS6 and DS7.
  • Feature tasks link to their feature artifact. Task AR belongs to Feature: Project artifacts standard; task MP to Feature: Model and effort profiles.
  • The task registry below the checklist is the record both artifacts are generated from. Once the plugin lands (AR12), set-task-status writes it and the hooks keep both artifacts published.
  • Recent releases are listed from the git history of main; a change merged to main is live through the marketplace’s auto-update.
  • The record of these artifacts is in docs/artifacts/ in this repo. A deleted artifact is recreated from it; see its README.
