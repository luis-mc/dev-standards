## What changed
- **Setting**: `record_dir` in `.claude/artifacts.json` (committed, relative, strictly under `docs/`). Absent file or key = `docs/artifacts`, so every other project is unchanged. The existing `.claude/artifacts-local.json` is git-ignored and per machine, so it was the wrong home for a project-wide path.
- **One resolver** in `artifact_queue.py` (`record_rel`, `check_record_rel`, `record_rel_safe`), used by:
  - `project_artifacts.py`: `Ctx` (so every command, lock, snapshot/restore, `pending`, `check`, `retire`, `mark-published`, publish logic), `check --record`, `path`, `worktree`, the "no record" and "commit" guard messages and the init/other messages.
  - hooks: `hook_after_command.py` (manifest, registry, origin reads via `git show origin/<branch>:<dir>/...`, history scan dir), `hook_end_of_turn.py`, `hook_session_start.py`, `publish_hourly.py`.
  - `render_artifacts.py` took no path (it gets `record_dir` from the caller); only a message changed.
- An unusable setting: commands exit 2 naming it; hooks fall back to the default (they never fail a turn).
- **`move-record NEW_DIR [--yes]`**: plain file move (no git), writes the setting (moving back to `docs/artifacts` removes the key), removes emptied parent folders under `docs/`. Dry run without `--yes`. Refuses an occupied target (exit 1), a nested/containing folder or a folder outside `docs/` (exit 2).
- Lock file and publish copy stay in `.claude/` (not record-dependent, as before). The one-time migration of the retired record worktree still reads `docs/artifacts` from the old worktree, as it always held that.
- **Spec**: new ARTIFACTSPEC §4.11 (R4.37, R4.38), command table row, config reference row, R13.1 range, via change note `docs/specs/changes/DS32-artifacts-record-dir.md` (spec + plugin, minor; no version edited, the fold bumps 1.15.0 -> 1.16.0 for both).
- Rule file line mentions the `record_dir` setting.
