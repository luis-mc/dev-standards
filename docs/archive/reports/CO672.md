# CO672 report: `project_artifacts.py retire`

Branch `claude/CO672-retire-features` (from `origin/main`), draft PR in dev-standards. The real project was read only: its `docs/artifacts` was copied to a scratch repo for the dry run and never written.

## Command
`project_artifacts.py retire <feature-key> [--yes] [--json]`
- Refuses (exit 1, nothing written) unless every task owned by the feature is Live or Dropped and it has no open decision. A feature with no tasks qualifies (the owner's 36 of 40 counts these).
- Without `--yes`: dry run. Prints the tasks kept, each file it would delete with its size, the total, and the archive it would write. Writes nothing.
- With `--yes`: moves the feature from `feature_artifacts` to a slim manifest list, copies `decisions.json` to `docs/artifacts/retired/<key>.decisions.json`, deletes `feature-<slug>.html` and `content/<key>/`, renders Full Progress, and leaves git alone. A result that would be invalid is put back (R7.1).
- The tasks keep their owner. `check` accepts a retired key as an owner; `task-add --owner <retired>` and `set-task-status` on its tasks are refused (history does not change).
- `feature-new` refuses a retired key unless `--force` (which brings the key back, so the old tasks belong to it again); a prefix held by a retired feature under another key is always refused.
- Full Progress section 1 gets one closed `<details class="retired-features">`, one `<li>` line each (title, key, retired date, decisions archive). No new CSS.
- It never touches a claude.ai page (R4.23).

## Deviations from the brief (please check)
1. The manifest list is named **`retired_features`**, not `retired`: `retired` already exists (R4.19) and holds old claude.ai pages to delete. Entry: `{key, title, prefix, retired, url, decisions}`. `prefix` is added because R4.6 needs it to validate the tasks' IDs.
2. **One small hunk in `render_artifacts.py`**: `_retired_fold()` plus one call at the end of `_feature_section`. Full Progress could not list the retired features otherwise. It adds no CSS and changes no existing markup. It uses a class outside `status-fold` / `feature-group` because the existing checks count those. CO669 should rebase cleanly unless it rewrites the end of `_feature_section`.
3. Images under `content/<key>/assets/` are not archived (the archive is the small `decisions.json` only), so an archived decision's image paths no longer resolve.

## Dry run on a real project (copy of `docs/artifacts`, 21 MB, 40 features)
- 36 of 40 features would be retired: 412 files, **12.25 MB** (feature html 6.75 MB, `content/` 5.5 MB), plus 34 decisions archives of 257.5 KB in total.
- Refused (open tasks): 4 features with Waiting, To do or Built tasks.
- 7 of the 36 have no tasks and are included on purpose.
- Trial of `retire --yes` on all 36 in the scratch copy: `docs/artifacts` 21 MB to 8.0 MB (`retired/` 332 KB). `check` findings 148 to 23; no retire-related finding (no R4.6, R4.31, R5.18). The 23 left are older findings in the four remaining features and two orphan content folders (R4.1), not caused by this change. The 148 before are mostly template drift (R5.10, R5.3, INV-3), which a `render` would fix.
- The real project was not changed. To apply: run the plugin's `retire <key> --yes` per feature in that project, after this plugin version is released.
